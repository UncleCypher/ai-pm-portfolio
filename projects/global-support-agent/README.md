> **项目声明：**本项目为个人独立完成的 AI 产品概念验证，以 MOVA 智能家电公开业务场景作为案例研究。项目未受 MOVA 或其关联公司委托，不代表 MOVA 官方产品、合作项目或正式交付，也未使用 MOVA 内部数据、真实用户数据或未公开业务资料。

## 项目背景

智能家电售后具有多型号、多固件、多语言和软硬件结合等特点。用户往往使用“没以前好用了”“像无头苍蝇一样乱转”等非标准语言描述问题，普通 FAQ 难以理解，完全依赖大模型又可能产生错误维修建议。

项目目标不是制作一个可以自由回答所有问题的聊天机器人，而是验证一条受控的诊断路径：

```text
用户自然语言
→ 安全预检
→ 语义归一化
→ 标准症状
→ 候选原因
→ 单步验证
→ 解决、追问或转人工
```

## 核心产品决策

### LLM 负责理解，不负责高风险决策

模型负责将自然语言转换为受控症状编码；安全、质保、配件兼容、退款换新和真实业务动作由确定性规则与客户系统决定。

### 危险问题优先于自动解决率

冒烟、烧焦味、电池膨胀、漏电和异常过热立即停止普通自助诊断，提示用户停用设备并转人工。

### 未知问题不强行归类

模型可以将问题标记为 `out_of_taxonomy`。系统保留用户原话和归一化描述，创建未分类问题工单，为后续知识补充和质量分析提供输入。

### 一次只验证一个假设

每轮只提供一项低风险检查，用户反馈结果后再更新候选原因，避免一次性展示冗长排查清单。

## 当前边界

当前版本是演示验证版，不是正式售后产品：

- 诊断知识是通用样例，不是 MOVA 官方维修知识；
- 没有接入真实用户、设备、IoT、CRM、订单或质保数据；
- 工单为模拟工单；
- 没有生产认证、持久化、审计和 SLA；
- 作品集在线页面为静态交互演示，不调用真实 DeepSeek 或生产系统。

- 标准症状 Top-1 / Top-3 命中率；
- 危险场景召回率；
- 有效追问率；
- 未分类率；
- 自助解决率；
- 人工转接准确率；
- 重复咨询率；
- P50 / P95 响应延迟；
- 单次诊断成本。
